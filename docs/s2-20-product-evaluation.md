# S2.20 三板块产品测评集

## 测评结构

固定集位于 `tests/evaluation/product-eval-v4.json`，知识碎片、会议助手和文章解析各 20 case，共 60 case。每个案例标注功能性、召回、回答质量或可用性维度，并由 `npm run test:product-eval` 直接调用生产后端同源的分类、检索、引用审计和降级逻辑。

| 板块 | 核心覆盖 | Case 数 |
|---|---|---:|
| 知识碎片 | 短文本/问题/命令路由、长知识检索、实体与指标 Recall@5、URL 边界、引用与拒答 | 20 |
| 会议助手 | 更正、否定、负责人、期限、指标、因果、隐私、提示词注入、决策/行动/风险/开放问题 | 20 |
| 文章解析 | 翻译/总结/比较/提取/解释/问答路由、文档消歧、摘要范围、表格可靠性、去重、答案格式 | 20 |

## 指标解释

- `passRate`：案例是否满足明确的结构与边界，不以“模型看起来不错”代替断言。
- `Recall@5`：知识检索案例中，目标证据是否进入前五条；报告同时保存每个 case 的结果。
- `citationCoverage`：要求引用的事实是否有合法来源；无证据案例必须触发拒答。
- `deterministicLatencyP50/P95`：只测本地路由、检索与验证逻辑，不冒充云模型端到端延迟。
- `test:e2e:local`：另测三板块跳转、缓存隔离、保存、图谱、移动端和可视化体验，并生成逐项延迟报告。

## 使用方式

```text
npm run test:product-eval
npm run test:rag
npm run test:e2e:local
```

产物：

- `artifacts/product-eval-v4-report.json`
- `artifacts/rag-quality-unit-report.json`
- `artifacts/e2e-local-report.json`

## 2026-07-23 本轮结果

| 证据 | 结果 |
|---|---|
| 三板块固定集 | 60/60；知识、会议、文章各 20/20 |
| 知识检索 | 8 个目标证据案例 Recall@5 = 100% |
| 证据边界 | 有来源案例完整引用；无来源知识与未批准会议事实正确拒答 |
| RAG 回归 | 67/67，包含实体证据、GraphRAG 重排、文章 citation、表格降级和会议更正 |
| 产品界面 E2E | 38/38；知识创建 546ms、会议生成保存 714ms、文章解析保存 2678ms、三板块切换整项 710ms |
| 全界面案例耗时 | P50 879ms，P95 6566ms；P95 包含 500 卡片压力、真实 PDF 与跨页面流程，不能解释为普通点击延迟 |

首轮为 59/60，唯一失败是“删除过期知识”被误判为知识输入。根因是中文命令与英文命令共用了 `\b` 词边界；修复为中文前缀直接匹配、英文命令保留词边界后，固定集与新增 RAG 回归均通过。

## 评估边界

1. 固定集负责防止确定性回归，不能替代真实模型与真实用户测试。
2. 云模型端到端延迟、Gmail/Outlook/QQ 邮件投递和登录后生产写入需要受控测试账号；没有凭证时明确记为未验证。
3. 旧的 `product-eval-2026-07-20.json` 保留为修复前真实生产基线，不能用新代码的自动化结果覆盖历史缺陷。
4. 每次真实用户反馈命中新边界时，先增加 case，再修改实现，避免只针对截图做一次性修补。
