# MindGrow 产品思路与技术栈概览

> 当前定位：证据优先、结构可维护的 AI 知识工作台。它不是“把资料塞进另一个聊天框”，而是把资料转成可引用、可编辑、可持续更新的知识网络。

## 1. 产品要解决的问题

传统 AI 问答有三个常见断点：

1. 答案与原文脱节，用户难以核验；
2. 结果停留在聊天记录里，不能持续维护；
3. 知识越积越多，检索噪声和导图拥挤同时增加。

MindGrow 的核心解法是把“证据、结构、回答”放进同一个闭环：

```text
网页 / PDF / 正文 / 会议
        ↓
结构化解析 + 逐字 Citation
        ↓
可编辑知识导图
        ↓
限定知识库检索 + 回答 / 拒答
        ↓
反馈、修订、合并，再沉淀回知识库
```

## 2. 产品定位与差异化

一句话定位：

**NotebookLM 式可信解析 + 可持续编辑的知识图谱 + 面向个人和小团队的低门槛使用。**

核心差异：

- **证据优先**：摘要、要点、论点、导图节点和 Audio Overview 都尽量绑定原文引用；证据不足时明确说明知识缺口。
- **结构优先**：AI 结果不是一次性答案，而是可以编辑、折叠、聚焦、导出和继续提问的知识结构。
- **渐进展示**：知识增长后不再强行把所有节点压进一个屏幕，而是先展示主干，再按需展开。
- **双模式交付**：未登录用户可直接使用本地模式；云端用户只需登录并选择工作区，不接触 Supabase Token 或 Workspace Token。
- **中国云栈可控**：静态前端、阿里云函数、通义千问/CosyVoice 与 Supabase 组合，适合快速上线和成本验证。

## 3. 目标用户与高价值场景

| 用户 | 任务 | MindGrow 输出 | 核心价值 |
|---|---|---|---|
| 研究者、学生、顾问 | 阅读网页、报告、PDF | 引用摘要、知识导图、Audio Overview | 加快理解且能回查原文 |
| 产品经理、分析师 | 竞品、访谈、行业研究 | 论点—证据结构、问题清单 | 缩短研究周期 |
| 项目团队 | 会议沉淀 | 决策、行动项、风险、知识节点 | 减少信息丢失 |
| 客服、售前、HR/IT | 高频制度与产品问答 | 权限范围内的可引用答案 | 降低重复咨询 |
| 小团队知识库 | 长期积累资料 | 可维护图谱、检索问答、反馈 | 让知识持续可用 |

## 4. 核心产品闭环

### 4.1 采集

- 直接输入知识碎片；
- 粘贴文章正文；
- 输入公开网页 URL；
- 上传原生 PDF；
- 粘贴会议记录或使用浏览器语音输入。

### 4.2 解析与可信化

AI 输出严格的结构化结果：摘要、要点、论点、导图和 citation indexes。后端只接受能在原文中找到的逐字引文，无法验证的引文会被丢弃或降级。

### 4.3 结构化沉淀

解析结果保存为知识节点、关系、来源文档和节点引用。用户可以编辑节点、调整结构、搜索、折叠、导出，并继续围绕当前知识库提问。

### 4.4 检索问答

当前版本在指定工作区与知识库范围内召回候选节点，再做受限的一跳图扩展。回答必须基于可用证据；知识库没有答案时，产品明确拒答或提示补充资料。

### 4.5 反馈飞轮

赞/踩、错误引用、无答案问题应逐步沉淀为评测集，用于回归检索、引用正确率、拒答准确率和体验完成率。

## 5. 大规模思维导图的信息压缩策略

产品原则不是“把 50 个节点缩得更小”，而是“减少同一时刻需要理解的节点”。

当前实现：

- 少于 14 个节点：默认展示全部；
- 14 个及以上：默认进入“主干”模式，使用横向结构；
- 主干模式展示根主题和一级分支，二级细节折叠为 `＋N`；
- 主干节点过多时，优先展开最近知识树，把较早知识树压缩成根主题卡片；
- 主干默认控制在约 12 个可见节点；
- 点击节点的 `＋N` 按分支展开，避免一次性炸开全图；
- 右键“聚焦此分支”只看一个子树，并可一键返回全图；
- “全部”模式保留给全局巡检，画布允许平移和缩放；
- 缩放较小时隐藏描述和引用徽标，只保留标题，形成语义缩放。

这套设计把导图从“静态海报”变成“可探索的知识导航器”。

## 6. Citation 与 Audio Overview 状态

Citation 已完成基础闭环：

- URL、粘贴正文和 PDF 均可解析；
- 摘要、要点、论点和导图节点可以绑定引用编号；
- 引文必须在源文本中真实存在；
- PDF 保留页码定位信息；
- 引用可以随知识节点保存；
- Audio Overview 脚本只能使用已验证的 citation indexes；
- 音频优先走 CosyVoice MP3，失败时降级为浏览器朗读。

当前边界：PDF 引用已有页码，但还没有内置 PDF Viewer 的“点击直达具体页和高亮原句”；导图引用当前以徽标/提示为主，后续应升级为统一证据侧栏。

## 7. 技术架构

```text
GitHub Pages / Browser
  Next.js + React + TypeScript
  React Flow + Zustand + Tailwind CSS
  Supabase Auth SDK + PDF.js
            │
            │ Authorization + X-Workspace-Id
            ▼
Alibaba Cloud Function Compute
  Node.js API / CORS / Auth / SSRF 防护 / 超时与大小限制
       ├── DashScope Qwen：结构化解析、知识回答、Audio 脚本
       ├── DashScope CosyVoice：临时 MP3
       └── Supabase：Auth + PostgreSQL + REST
              ├── workspaces / members
              ├── knowledge_maps / nodes / edges
              └── source_documents / node_citations
```

## 8. 技术栈明细

| 层 | 技术 | 作用 | 选型原因 |
|---|---|---|---|
| Web 框架 | Next.js 15、React 18、TypeScript | 页面、组件、静态导出和类型安全 | 兼顾复杂交互和 GitHub Pages 静态发布；类型系统可降低节点、引用和 API 数据结构的出错率 |
| UI | Tailwind CSS 3 | 主题、响应式布局和交互状态 | 适合快速迭代统一暗色主题、桌面端和移动端，减少分散样式维护 |
| 导图 | React Flow 11 | 节点、边、缩放、平移、缩略图和自定义节点 | 直接覆盖导图基础能力，支持自定义节点与渐进展示，避免从 Canvas 底层自研 |
| 前端状态 | Zustand 4 | 知识库、节点、聊天、折叠、撤销/重做等状态 | 比 Redux 更轻，适合当前团队规模；又能避免跨组件层层传参 |
| 本地模式 | Browser LocalStorage + 本地 API 适配层 | 无账号即可体验完整主流程 | 降低首次使用门槛，支持低成本演示；适配层让本地和云端共用主要 UI |
| 登录 | Supabase Auth、supabase-js 2 | 邮箱注册、登录、会话保存与自动刷新 | 快速获得成熟认证和会话刷新，普通用户不需要接触任何 Token |
| 数据库 | Supabase PostgreSQL | 多租户工作区、知识图谱、来源和引用 | 关系模型适合图谱关系、来源和权限；保留标准 PostgreSQL 的可迁移性 |
| 后端 | 阿里云函数计算，Node.js | 统一 API、身份/成员校验、模型和数据库代理 | 静态前端必须有安全代理保存密钥；按量付费且无需长期维护服务器 |
| 大模型 | DashScope Qwen | 结构化解析、回答、会议纪要、Audio 脚本 | 中文能力和结构化输出适配较好，与阿里云函数同云部署可降低调用复杂度 |
| 语音 | DashScope CosyVoice + Web Speech 降级 | Audio Overview | CosyVoice 提供自然中文语音；浏览器朗读保证外部音频失败时功能仍可用 |
| PDF | pdfjs-dist | 浏览器本地提取文本与页码 | 减少文件上传、隐私风险和后端带宽，同时保留页码定位 |
| 导出 | html-to-image、jsPDF | PNG、PDF、Markdown 输出 | 浏览器端即可完成常用交付格式，避免增加后端渲染服务 |
| 部署 | GitHub Pages + 阿里云函数 + Supabase | 低运维、按量扩缩 | 静态前端托管成本低；计算和数据服务独立扩展，适合 MVP 阶段验证 |
| 质量 | ESLint、Next Build、Puppeteer E2E、后端冒烟脚本 | 构建、端到端、移动端、Citation 和安全验证 | 真实风险集中在跨模块用户链路，浏览器级测试比只测单个函数更接近实际体验 |

总体选型原则：**MVP 阶段优先低成本、低运维、快速验证；安全与租户隔离不妥协；模型、数据和部署层都通过适配边界保留替换空间。**

## 9. 安全与多租户原则

- 普通用户永远不手工复制登录令牌或工作区令牌；
- 浏览器只持有 Supabase 可公开的 publishable key 和用户短期会话；
- Supabase service-role/secret key 与 DashScope key 只在阿里云函数环境变量中；
- 每个云端请求同时校验用户身份、Workspace 成员关系和资源归属；
- 匿名用户不能直接读写业务表；
- URL 抓取需要阻止内网地址、限制响应大小并设置超时；
- 跨租户数据泄漏是发布阻断项。

## 10. 当前边界与下一阶段

当前版本已经跑通“采集—解析—引用—导图—检索—回答—反馈”的 MVP 闭环，适合个人和小团队的小到中等知识库。

下一阶段优先级：

1. **检索质量**：结构化分块、Embedding、关键词/稀疏召回、RRF、Qwen Rerank；
2. **引用体验**：PDF/网页深链、原文高亮、统一证据侧栏；
3. **知识治理**：去重、冲突、新鲜度、专家验证、版本历史；
4. **团队能力**：邀请、RBAC、审计、云端反馈与查询日志；
5. **来源生态**：Notion、Google Drive、Slack、Confluence、DOCX/PPTX/OCR；
6. **国际化**：英文 UI、隐私/删除流程、国际用户反馈社区。

建议北极星指标：

**每周被再次使用且至少有一个有效 Citation 的知识节点数。**

它同时衡量知识是否被沉淀、是否可信，以及是否真正产生了复用价值。
