# MindGrow 产品说明书

## 1. 产品定义

MindGrow 不是通用聊天机器人，而是“知识采集 → 结构化 → 证据检索 → 回答 → 反馈 → 再沉淀”的个人知识闭环。它优先服务个人研究者、产品经理、顾问与小团队，先以无需注册的本地模式降低首次使用成本，再以云端同步、权限和连接器扩展到团队场景。

核心承诺：

1. 回答先找证据，证据不足就拒答。
2. 用户能看到并编辑知识结构，而不是把知识锁在聊天记录里。
3. 默认本地可用；云服务故障时，基本产品仍可运行。

## 2. 核心用户任务

| 用户任务 | 触发 | 产品响应 | 成功信号 |
|---|---|---|---|
| 记录知识 | 输入想法、事实或资料片段 | 生成主题/概念/细节结构，确认后保存 | 60 秒内完成首个知识结构 |
| 回忆事实 | 输入明确问题 | 检索当前知识库、列出编号证据 | 用户在 2 次点击内回到证据 |
| 发现缺口 | 问题无充分证据 | 明确拒答并建议补充资料 | 无依据回答率趋近 0 |
| 整理主题 | 打开知识导图 | 搜索、编辑、移动、折叠、删除节点 | 用户能持续维护而非一次性生成 |
| 复用成果 | 需要分享或存档 | 导出 Markdown、PNG 或 PDF | 导出成功率 ≥99% |

## 3. 已实现范围

- 多知识库、文件夹、模板和浏览器持久化。
- AI/规则化知识结构生成与用户确认。
- 当前知识库检索、编号引用、无答案拒答。
- 回答赞/踩反馈记录。
- 可编辑知识导图、搜索、布局、撤销重做和导出。
- 桌面和移动端适配。
- 本地优先/云端 API 双模式。
- SEO 指南页、站点地图、robots、Open Graph、FAQ 与 SoftwareApplication 结构化数据。
- 阿里云函数健康检查、稳定错误码、请求超时、输入大小限制、可逆后端冒烟测试。

## 4. 仍未实现的产品能力

- 文件、URL、云盘与企业应用连接器。
- 文档切片、向量索引、混合检索、重排和语义答案合成。
- 账号、组织、角色、文档级权限与审计日志。
- 云端反馈存储、国际用户社区、工单和自动评测平台。
- 英文 UI、真实多语言内容页与 `hreflang`。
- 增量同步、版本历史、引用定位到原文段落。

## 6. 技术思路

### 前端

Next.js 静态导出 + React + Zustand + React Flow。`client-api` 层保持统一的 HTTP 风格接口：未设置云端地址时读写 `localStorage`；设置云端地址时请求阿里云函数。这样能在云依赖不可用时保留完整的核心演示与个人使用路径。

### 云端

阿里云函数是唯一可信边界：负责 CORS、输入校验、错误码、超时、DashScope 调用和 Supabase CRUD。Supabase secret/service-role key 与 DashScope key 不进入浏览器。

### 检索

MVP 使用可解释的词项/中文双字匹配，对命中节点按覆盖率排序，最多返回 5 条证据；无命中时明确拒答。P1 应升级为 BM25 + embedding 混合召回、cross-encoder 重排，并保持逐句引用与拒答阈值。

## 7. 路线图

| 阶段 | 目标 | 退出标准 |
|---|---|---|
| P0 | 本地闭环与云端恢复 | 本地 8/8；后端 13/13；0 高危依赖 |
| P1 | 可用的 RAG | 文件/URL 导入、混合检索、引用跳转；Recall@5 ≥85%，引用正确率 ≥95% |
| P1 | 团队安全 | 登录、多租户、权限过滤、审计；跨租户泄漏 0 |
| P2 | 质量飞轮 | 线上反馈、知识缺口队列、离线评测和回归门禁 |
| P2 | 国际化 | 英文 UI/内容、时区与隐私流程、英语用户反馈群 |
| P3 | 工作流与连接器 | Google Drive/Notion/Slack/Confluence 等连接器和可配置 Agent |
