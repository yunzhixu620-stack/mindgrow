# P2.1.2 description grounding 阈值标定报告

状态：等待 Owner 确认建议初值；生产代码尚未写入 coverage 常量。

## 1. 样本与方法

- 冻结样本：`tests/fixtures/entity-quality/description-grounding-calibration.json`
- 总量：20 条，其中正样本 12 条、负样本 8 条。
- 覆盖：英文论文、中文论文、会议纪要、缩写/别名、跨语言技术词、数字/百分比、否定事实、错误负责人、实体共现但事实错误。
- 可复现命令：`node scripts/entity-description-calibration.js`
- 固定前置门：实体名或可靠 alias 命中、description 专属证据合法、数字逐字一致、肯否极性一致。
- 当前合并候选门：去停用词后至少命中 2 个有效锚点。coverage 只做标定，Owner 确认前不参与生产判定。

## 2. 有效锚点分布

| 集合 | anchor 数范围 | 命中数范围 | coverage 范围 |
|---|---:|---:|---:|
| 支持（12） | 7–27 | 5–16 | 0.346–1.000 |
| 不支持（8） | 13–28 | 0–14 | 0.000–0.583 |

中文使用二元片段后 anchor 数显著高于英文，因此不能直接用一个较高 coverage 值同时约束中英文。负样本中的“BM25 与 DPR 同句共现，但把 BM25 错说成 DPR 的编码器”达到 0.583，说明词面 coverage 无法替代语义蕴含判断。

## 3. 精度与保留率

固定前置门 + “至少 2 个锚点”基线：

- TP 12、FP 1、FN 0、TN 7
- precision 92.3%
- retention 100%

按 v4 的 `matchedAnchors >= 2 OR coverage >= threshold` 形式测试 0.25、0.34、0.40、0.50、0.60，本批样本结果均与基线相同：precision 92.3%，retention 100%。原因是全部有效正样本已经满足“两锚点”，coverage 分支没有额外救回样本。

coverage 单独作为门时的敏感性如下（用于理解阈值代价，不代表建议改成单阈值门）：

| coverage | precision | retention | TP / FP |
|---:|---:|---:|---:|
| 0.25 | 92.3% | 100% | 12 / 1 |
| 0.34 | 92.3% | 100% | 12 / 1 |
| 0.40 | 90.9% | 83.3% | 10 / 1 |
| 0.50 | 85.7% | 50.0% | 6 / 1 |
| 0.60 | 100% | 41.7% | 5 / 0 |

## 4. 建议初值

建议把 **0.34** 作为 coverage 备用分支的初值，但仅在 Owner 确认后加入生产代码，且继续保留以下硬门：

1. coverage 不能绕过实体名/alias 命中；
2. coverage 不能绕过数字逐字一致与肯否极性一致；
3. 至少命中 1 个有效锚点，禁止 `0 / N` 仅靠空分母通过；
4. `descriptionEvidence` 缺失时直接失败，严禁从 `citationIndexes` 复制或派生。

选择 0.34 的原因：它贴近当前正样本最低值 0.346，完整保留本批中英论文、会议和跨语言样本；0.40 已损失两个有效样本。它并不能消除“高词面重叠但语义角色错误”的 FP，后者应由后续固定评测集、关系/角色验证或独立 entailment 判定处理，不能继续抬高 coverage 来掩盖。
