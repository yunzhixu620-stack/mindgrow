# MindGrow GraphRAG 检索与三栏工作区说明

## 目标

解决纯向量检索容易把“语义相近、事实对象不同”的内容混在一起的问题，并让文章解析、会议助手和知识碎片使用一致的知识图谱交互方式。

## 检索链路

1. **查询锚点**：从问题中保留论文名、模型名、任务名、指标和数字等高区分度词，过滤“论文、方法、什么”等泛词。
2. **图谱入口召回**：在当前产品的独立知识库中检索入口节点，按锚点覆盖率和文本检索分数排序。
3. **两跳邻域扩展**：沿 `contains` 和 `relates_to` 关系扩展两跳，第一跳取得父子证据，第二跳取得兄弟主题和跨论文关联。
4. **节点到文档桥接**：通过 `node_citations` 将命中的图谱节点反查到来源论文/会议，再把这些文档作为结构约束。
5. **混合召回**：在 `document_chunks` 中并行使用全文检索与 1024 维向量检索。
6. **图谱条件化排序**：属于图谱关联文档、命中查询锚点的证据块获得结构加权；仅语义相似但不在相关子图内的块降权并限制数量。
7. **重排与回答**：使用重排模型选取最终证据；回答模型只能引用候选证据 ID，最终返回逐字 quote、文档标题和页码/段落定位。

## 文章对话意图路由

文章工作区不会再把所有输入都当作 Citation 问答。请求先被识别为“翻译、总结、解释、比较、信息提取、事实问答”之一，再进入对应任务提示词：

- 翻译请求直接读取目标论文的有序原文分块，不使用“翻译这篇论文”作为语义检索问题；
- 多篇论文且未指定标题时先澄清，避免翻译错文档；
- 整篇论文超过单次输出容量时要求用户指定摘要、章节或页码，避免输出被截断却误报为全文；
- 翻译内容默认使用简体中文，原文引用继续保留原语言用于逐字核验；
- 事实问答、跨论文比较等任务继续使用 GraphRAG 与 Citation 约束。

论文解析结果在返回前还会执行中文字段校验；若标题、摘要或导图节点仍是英文自然语言，则只对结构化文本做二次中文本地化，节点引用编号、数组顺序和原文 quote 不参与翻译。

## 防误召回策略

- 论文根节点只有在高度相似时才复用，避免不同论文因主题接近被错误合并。
- 跨论文只建立高阈值、共享多个锚点的 `relates_to` 关系。
- 检索最多扩展两跳和有限节点数，避免全图噪声进入上下文。
- 表格列边界不可靠时拒绝猜数字；原始 PDF 保留制表位后才允许返回精确表格值。
- 证据不足时明确拒答，不用模型常识补齐数据库没有的事实。

## 页面结构

桌面端三个产品统一为：

`左侧独立知识库目录 → 中间输入/解析/问答 → 右侧可交互知识图谱`

文章或会议解析完成后，右侧先生成临时预览图；保存后重新载入 Supabase 中的持久化节点、关系和引用。移动端通过“内容 / 图谱”标签切换。

右侧关系图中，实线表示层级包含，粉色虚线表示概念关联，红色虚线表示观点冲突。顶部“生长中”状态显示节点、连接、语义关系和引用覆盖；知识宇宙进一步把同板块的多个知识库聚合为星系簇，并用共享概念或主题相关度显示跨库导航关系。

## 项目卡跳转问题

旧版由项目卡、首页地图监听和产品模式监听同时发起加载请求。旧请求晚返回时会覆盖用户最后一次点击，造成项目在界面上反复跳转。修复后：

- 左侧项目严格按当前产品模式过滤；
- 所有桌面端、移动端、左侧目录和顶部标签都只修改目标知识库 ID；
- 页面只有一个权威图谱加载器，每次加载带递增请求序号；
- 只有最后一次点击对应的响应可以更新节点和关系；
- 切换板块或知识库时先原子清空旧节点，避免旧板块残影；
- 后端继续校验会议/文章库标记，防止跨产品写入。

## LLM Wiki + 实体知识图谱升级方案

### 当前能力边界

10.5.2 已交付 L1 实体层和 L2 检索层的核心链路：文章解析和会议助手会在概念导图之外自动抽取带类型的实体、有向关系和逐字证据；右侧工作区可以在“概念图 / 实体图”之间切换，点击关系边可直接查看证据。实体、关系如果没有当前来源的 Citation，或低于置信度门槛，不会进入持久化图谱。查询时会执行精确别名入口、类型与状态约束、关系白名单、最多两跳扩展、证据重排和歧义拒答。

现有 `relates_to` 仍属于概念图关系，主要来自高阈值文本相似和共享锚点；新的实体图以 `source_entity_id → target_entity_id` 表示方向，并与用户编辑的主题/概念/细节层级分表保存，避免自动抽取改写或降级原导图。

完整的 LLM Wiki 仍需继续补齐以下能力，其中前 3 项的 L1 基础已经上线：

1. **实体抽取**：从网页、PDF、粘贴正文和会议转写中抽取人物、组织、模型、方法、数据集、指标、任务、事件、决策和时间。
2. **概念与声明抽取**：区分概念定义、可验证声明、假设、风险、已否决决议和历史版本，不能把它们都保存为普通概念。
3. **有向关系抽取**：保存 `提出`、`使用`、`评测于`、`依赖`、`优于`、`反驳`、`负责`、`截止于` 等带方向和状态的关系。
4. **实体消歧与合并**：为中英文名称、缩写和别名生成规范实体 ID；同名但不同来源/时间/类型的实体不得自动合并。
5. **关系级溯源**：每个实体和每条关系都必须绑定原文分块、页码/段落、逐字引用、抽取置信度和模型版本；无原文证据的关系不进入检索主图。

### 推荐数据模型

不要直接扩展旧 `nodes.type` 和 `edges.relation` 的 CHECK 约束。旧表继续负责用户可编辑的导图，新增独立的实体图表，避免迁移影响现有知识库：

| 表 | 关键字段 | 用途 |
|---|---|---|
| `graph_entities` | `id`、`canonical_name`、`entity_type`、`aliases`、`description`、`confidence`、`map_id` | 规范实体与别名 |
| `graph_relations` | `source_entity_id`、`target_entity_id`、`relation_type`、`direction`、`status`、`valid_from/to`、`confidence` | 有向、带状态和时效的关系 |
| `graph_evidence` | `entity_id/relation_id`、`document_id`、`chunk_id`、`quote`、`locator` | 实体和关系的逐字证据 |
| `graph_communities` | `community_id`、`level`、`summary`、`member_ids`、`source_version` | 大图的社区聚类与 Wiki 目录摘要 |
| `entity_aliases` | `alias`、`normalized_alias`、`entity_id`、`language` | 精确别名入口和消歧 |

所有表继续带 `workspace_id` 与 `map_id`，由阿里云函数校验用户、工作区和知识库归属，Supabase 只允许 service role 访问。

### 索引与生成链路

`资料读取 → 原文切块 → 实体/概念/声明/关系候选抽取 → 逐字证据校验 → 实体消歧 → 写入实体图 → 社区检测与 Wiki 摘要 → 嵌入与检索索引`

- 抽取模型只能引用当前批次的 `chunk_id`，不能用模型常识补关系。
- 关系缺少主语、宾语或逐字证据时降级为待确认候选，不写入主图。
- 实体自动合并需要同时满足别名、类型、来源上下文和时间一致；候选分差过小则保留两个实体并提示人工确认。
- 社区摘要属于派生数据，原节点和原关系始终完整保留；重新聚类只改变概览展示，不改变事实层。

### Graph View 产品形态

右侧工作区增加三个无损视图层级：

1. **Wiki 目录**：按文档/章节/社区展示摘要，适合快速阅读和论文定位。
2. **概念图**：保留现有主题—概念—细节导图，适合整理与编辑。
3. **实体图**：显示实体类型、方向关系、证据数量和置信度，适合 GraphRAG 检索解释。

默认只展示社区概览和高置信关系，点击 `+N` 后原实体、原关系和原层级完整恢复。筛选器支持实体类型、来源文档、时间、关系类型、置信度和“仅看有引用”；点击关系边直接打开原文证据，而不是只显示抽象标签。

### 大图渐进式披露：Heptabase × Mem

MindGrow 不把“大图看不清”理解为单纯缩小卡片。Heptabase 官方建议大白板拆成子白板并按需折叠卡片，因为 100–150 张卡片已经可能产生明显性能与认知负担；其 AI 工具链也是先搜索对象/白板，再按需读取单个对象或 PDF 局部。Mem 则通过 Collections、自动归类和搜索，把同一条笔记放入多个上下文，并只在需要时浮现相关信息。

MindGrow 采用二者的互补逻辑，同时保留自己的 GraphRAG 证据优势：

1. **逐层展开**：总览、主题、概念、细节按层级展开。点击节点 `＋N` 只显示 N 个直接子节点；新出现但仍有后代的节点保持折叠，不会一次展开整棵树。
2. **分支聚焦**：每个非总览父节点提供 `◎`，进入只看当前子树的阅读空间；按 Esc 或顶部“返回全图”恢复上下文。这对应 Heptabase 的白板/子白板聚焦，但不新建或改写知识节点。
3. **信息密度切换**：`智能` 随缩放自动决定摘要可见性；`仅标题` 提高节点显示率；`阅读卡` 始终显示摘要和 Citation。密度是视图状态，不压缩原始内容。
4. **卡片层级格式**：标题两行、摘要三行、Citation 独立成行并左对齐；颜色只表达一级分支，不让颜色承担事实分类。
5. **显式全图**：只有顶部“全部”按钮才执行全展开，作为导出、全局检查和高级用户操作；节点上的 `＋N` 永远不是“全部展开”。
6. **后续 Mem 式上下文浮现**：搜索命中隐藏节点时自动展开祖先路径，并在右侧显示命中卡片、所属主题、来源与邻近节点；不要求用户先在大图里找到它。

实现只操作 `collapsedNodes`、聚焦分支与渲染密度，不写回 Supabase 的节点层级、关系和 Citation，因此不会为了 UI 清晰而降低信息密度或破坏 GraphRAG 拓扑。

参考：[Heptabase 大白板性能与折叠建议](https://support.heptabase.com/en/articles/11430704-troubleshooting-performance-and-lag-issues-in-heptabase)、[Heptabase 按白板与对象逐级读取](https://support.heptabase.com/en/articles/12679581-how-to-use-heptabase-mcp)、[Mem Collections](https://help.mem.ai/features/collections)。

### 防止 GraphRAG 定位不准

查询阶段采用“先锁实体，再扩关系，最后回原文”的约束链路：

1. 查询分类为精确事实、实体关系、多跳探索或全库概览。
2. 别名精确匹配、BM25、向量召回并行产生实体候选。
3. 使用实体类型、来源文档、时间、版本和上下文做消歧；前两名分差不足阈值时先向用户澄清。
4. 按问题类型设置关系白名单，默认最多两跳，并对高连接度中心节点降权。
5. 用实体锚点、关键词、向量、图路径、元数据和时效联合重排。
6. 图谱只负责召回候选；回答中的每个可验证结论必须回到 `graph_evidence` 或 `document_chunks`，否则拒答。

### 分阶段交付

| 阶段 | 范围 | 上线门槛 |
|---|---|---|
| L1 实体层 | 实体/别名/关系/证据表，文章与会议自动抽取，实体 Graph View | 实体与关系均可点回原文；无证据关系不入库 |
| L2 检索层 | 实体精确入口、消歧、关系白名单、路径重排、拒答 | Entity Hit@5 ≥ 95%；Citation Precision ≥ 95% |
| L3 Wiki 层 | 社区检测、目录页、社区摘要、增量重建 | 大图首屏 ≤ 30 个聚合项；展开后信息零丢失 |
| L4 评测层 | 人工金标实体/关系/路径集，错误样本回灌 | Gold Path Recall@10 ≥ 90%；无依据事实率 ≤ 2% |

当前进度：L1 已在 10.4.3 上线；10.5.2 已把 L2 的精确别名、实体类型提示、查询计划、关系白名单、1–2 跳约束、路径/证据重排、否定与历史关系降权、歧义澄清接入正式检索链路。L3 社区 Wiki 和 L4 人工金标路径集仍是后续范围；实体自动合并仍坚持保守策略，不在证据不足时强行消歧。

### 会议可靠模式与运行时兼容

10.21.24 默认启用模型增强生成会议主题、决议、行动项、风险、开放问题、Citation 与实体图；显式设置 `MEETING_AI_ENHANCEMENT=false` 可关闭。增强失败时自动回退到证据优先解析。回退解析会忽略来源 URL、Presenter、Conclusion 等元数据，并优先识别明确的 consensus、Stage 变更、PR 合并和提案撤回，避免把技术语句里的 `reject` 误判为未决问题。

阿里云函数当前使用旧版 Node 自定义运行时，因此后端保持 ECMAScript 2018 兼容，并禁止依赖 `Array.prototype.flatMap` 等该运行时缺失的 API。每次发布前的 RAG 质量测试会解析后端源码并检查兼容性，防止出现“本地通过、云端 503”。
