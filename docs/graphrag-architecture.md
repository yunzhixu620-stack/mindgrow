# MindGrow GraphRAG 检索与三栏工作区说明

## 目标

解决纯向量检索容易把“语义相近、事实对象不同”的内容混在一起的问题，并让文章解析、会议助手和知识碎片使用一致的知识图谱交互方式。

## 检索链路

1. **查询锚点**：从问题中保留论文名、模型名、任务名、指标和数字等高区分度词，过滤“论文、方法、什么”等泛词。
2. **图谱入口召回**：在当前产品的独立知识库中检索入口节点，按锚点覆盖率和文本检索分数排序。
3. **两跳邻域扩展**：沿 `contains` 和 `relates_to` 关系扩展两跳，第一跳取得父子证据，第二跳取得兄弟主题和跨论文关联。
4. **节点到文档桥接**：通过 `node_citations` 将命中的图谱节点反查到来源论文/会议，再把这些文档作为结构约束。
5. **混合召回**：在 `document_chunks` 中并行使用全文检索与 1024 维向量检索。
6. **图谱条件化排序**：属于图谱关联文档、命中查询锚点的证据块获得结构加权；仅语义相似但不在相关子图内的块降权并限制数量。
7. **重排与回答**：使用重排模型选取最终证据；回答模型只能引用候选证据 ID，最终返回逐字 quote、文档标题和页码/段落定位。

## 防误召回策略

- 论文根节点只有在高度相似时才复用，避免不同论文因主题接近被错误合并。
- 跨论文只建立高阈值、共享多个锚点的 `relates_to` 关系。
- 检索最多扩展两跳和有限节点数，避免全图噪声进入上下文。
- 表格列边界不可靠时拒绝猜数字；原始 PDF 保留制表位后才允许返回精确表格值。
- 证据不足时明确拒答，不用模型常识补齐数据库没有的事实。

## 页面结构

桌面端三个产品统一为：

`左侧独立知识库目录 → 中间输入/解析/问答 → 右侧可交互知识图谱`

文章或会议解析完成后，右侧先生成临时预览图；保存后重新载入 Supabase 中的持久化节点、关系和引用。移动端通过“内容 / 图谱”标签切换。

## 项目卡跳转问题

旧版由项目卡、首页地图监听和产品模式监听同时发起加载请求。旧请求晚返回时会覆盖用户最后一次点击，造成项目在界面上反复跳转。修复后：

- 左侧项目严格按当前产品模式过滤；
- 每次地图加载带递增请求序号；
- 只有最后一次点击对应的响应可以更新节点和关系；
- 后端继续校验会议/文章库标记，防止跨产品写入。
