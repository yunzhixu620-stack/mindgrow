# S2.14 统一知识宇宙

## 用户可见结果

- 知识宇宙会把文章、会议和知识碎片中相同的实体显示为一个工作区共享实体，而不是三个重复圆点。
- 共享实体以金色、大尺寸节点区分；悬停显示来源知识库数量与名称，点击后汇总各来源的别名、说明证据、普通引用和直接关系。
- 只合并同一实体类型下的精确规范名或可靠别名；不同类型的同名词不合并，过短别名不会触发自动合并。
- 会议分析结果先显示为“预览草稿”。只有用户点击“确认并加入长期知识库”后，节点、引用和实体才会进入会议库与统一知识宇宙。
- 未确认的会议保存请求会由本地模式和阿里云后端同时拒绝，并返回 `MEETING_CONFIRMATION_REQUIRED`。

## 技术与数据边界

- 不新增数据库迁移，不跨库改写、搬迁或删除 `graph_entities`。每个 map 的实体 id 继续作为证据归属、租户权限和回滚边界。
- 后端为实体增加稳定的 `workspaceEntityId` 只读投影；前端在同工作区内按规范名、可靠别名和实体类型做确定性聚合。
- `/api/knowledge?action=universe` 在原有一次浏览器请求内并行读取实体/关系证据和来源文档，使统一实体详情仍可核验引用；没有新增逐库网络请求。
- 聚合接口继续限制最多 500 个知识库、12,000 个实体、24,000 条关系、48,000 条证据和 6,000 个来源文档，避免无界加载。
- 会议写入门禁使用严格布尔值 `confirmedForLongTerm: true`；字符串或缺失值不能绕过。

## 安全与正确性

- 租户隔离不变：所有聚合查询继续以服务端解析出的 `workspace_id` 过滤，客户端不能指定其他工作区。
- 共享实体 id 包含工作区，因此同名实体不会跨租户合并。
- 自动统一是可重建的只读视图；不生成新事实，也不把语义相似当作身份相同。
- 聚合后的实体说明优先采用有专属证据、置信度更高的来源，其余来源只补充引用、别名和直接关系。
- 文章与知识碎片写入协议不受会议确认门禁影响。
