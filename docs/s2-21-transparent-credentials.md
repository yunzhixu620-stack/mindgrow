# S2.21 普通用户凭证透明化

## 用户体验承诺

- 普通用户只需要邮箱和密码，不复制 Supabase 登录令牌，也不配置“工作区令牌”。
- 登录会话由 Supabase SDK 存在浏览器安全会话存储中并自动续期；应用请求自动附带当前会话。
- 工作区 ID 只是已登录用户选择的数据范围，不是访问凭证。后端仍会校验用户是否属于该工作区。

## 请求与续期策略

1. 每次云端请求从 Supabase 读取当前会话，并覆盖调用方传入的 `Authorization` 与 `X-Workspace-Id`。
2. 请求返回 401 时，应用只刷新一次会话并只重试一次。
3. 同一时刻的多个 401 共用一次刷新，避免高频使用时形成刷新风暴。
4. 刷新失败时返回原始 401，不无限循环、不把令牌写入错误提示，也不因一次网络波动自动清空本地数据。
5. 匿名状态不发送 Authorization；未选择工作区时不发送工作区头。

## 最小权限边界

- 前端只持有 Supabase publishable key 和当前用户短期会话。
- Supabase service-role、数据库管理凭证和模型密钥只存在于阿里云函数环境变量。
- 后端从受验证的登录会话取得用户身份，并独立校验 workspace membership；前端工作区 ID 不能越权。
- 退出登录会清除租户缓存和活动工作区上下文。

## 验证证据

- 单元测试覆盖托管头覆盖、401 单次刷新、二次 401 不循环、刷新失败、匿名请求和并发刷新合并。
- 公开页面 E2E 验证登录页没有 token 输入框，并明确提示用户无需配置令牌。

## 工程影响与回滚

- 主要文件：`src/lib/managed-session.ts`、`src/lib/client-api.ts`、`src/lib/i18n.ts`、单元测试、公开 E2E 与本说明。
- 未新增依赖、数据库迁移或后端接口，不改变 Citation、GraphRAG、URL 读取与租户成员校验。
- 健康会话仍只发送一次业务请求；仅在 401 时增加一次刷新和一次重试，并发 401 共用刷新。38 项本地产品 E2E 全通过，三板块切换整项 710ms，无可测回归。
- 回滚可单独回退 PR #64，恢复 SDK 自动刷新但移除 401 主动补偿；不会删除账号、工作区或本地知识数据。
- 仍未进行人为篡改真实生产 access token 的破坏性测试；该边界由冻结单测与后端匿名/成员校验门禁覆盖。
