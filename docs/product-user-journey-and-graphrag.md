# MindGrow 产品链路、使用方式与 GraphRAG 优势

## 一句话产品定义

MindGrow 是一个“证据先行、结构持续生长”的 AI 知识工作台：用户把碎片、会议和文章放进各自独立的知识库，系统生成可引用的节点与关系，再通过 GraphRAG 从正确实体和正确来源组织回答。

## 1. 三个产品板块的关系

| 板块 | 输入 | 中间结果 | 沉淀结果 | 典型使用 |
|---|---|---|---|---|
| 知识碎片 | 想法、笔记、问题 | 可编辑的主题—概念—细节结构 | 长期个人知识网络 | 第二大脑、学习、产品研究 |
| 会议助手 | 会议原文、语音转写 | 摘要、决议、行动项、风险和引用 | 独立会议知识库 | 会后追踪、团队决策 |
| 文章解析 | 网页、URL、PDF、正文 | 中文摘要、论点—证据、引用、音频概览 | 独立文章/论文知识库 | 论文阅读、行业研究 |

三个板块共用同一套“左侧知识库 → 中间工作区 → 右侧知识图谱”交互，但数据按板块和知识库隔离。切换顶部标签时，系统直接恢复该板块上次使用的知识库；任何旧请求都不能覆盖当前板块。

## 2. 从输入到复用的完整产品链路

```text
输入碎片 / 会议 / 网页 / PDF
        ↓
解析并切分为可核验证据块
        ↓
生成中文摘要、要点、实体和关系
        ↓
逐项绑定 Citation（来源、页码/段落、原文）
        ↓
保存为知识节点 + 层级关系 + 语义关系
        ↓
主干压缩 / 分支展开 / 搜索 / 知识宇宙
        ↓
GraphRAG：实体入口 → 两跳邻域 → 来源文档 → 混合召回 → 重排
        ↓
带引用回答，或在证据不足时拒答
        ↓
编辑、删除、反馈和新资料继续让图谱生长
```

## 3. 多个知识库之间到底是什么关系

关系分为两层，二者含义不同：

1. **库内事实关系**：来自保存后的节点边，包括“包含”“概念关联”“观点冲突”。这些关系可以参与当前知识库的 GraphRAG 检索。
2. **跨库导航关系**：知识宇宙比较多个同板块知识库中的共享概念和主题词，显示“共享概念”或“主题相关度”。它用于发现可合并、可对照的研究链路，但不会被当作原文事实或伪造 Citation。

文章库之间默认不会混成一个检索空间。这是有意设计：先保证论文 A 的问题不会被论文 B 的相似段落错误回答。用户可以在知识宇宙看到跨库联系，点击节点回到所属文章库，再在明确范围内提问。

## 4. “可生长”如何在界面上体现

- 每次保存内容都会新增或复用节点，而不是只留下聊天记录；
- 实线代表主题层级，带文字的虚线代表概念关联或观点冲突；
- 右侧显示“生长中”的节点数、连接数、语义关系数和可追溯节点数；
- 大图默认只显示主干，节点上的 `＋N` 可以逐支展开；
- 知识宇宙把同板块的多个知识库显示为星系簇，黄色虚线表示跨库生长关系；
- 继续加入同主题文章时，共享实体会形成新的跨库连接；
- 用户可以删除多余知识库，删除只影响当前库，不污染其他板块。

## 5. 用户最快使用路径

### 研究论文

1. 点击顶部“文章解析”；
2. 在左侧创建一个以课题或论文命名的文章库；
3. 上传 PDF、粘贴 URL 或正文；
4. 核对中文摘要、引用和右侧图谱；
5. 保存后在当前文章库提问；
6. 打开“知识宇宙”查看不同论文库的共享概念和主题关系。

### 会议沉淀

1. 点击“会议助手”；
2. 录入会议原文或使用语音输入；
3. 检查决议、行动项、风险及引用；
4. 保存到会议知识库；
5. 后续按项目搜索会议库或通过图谱定位决策链。

### 日常知识

1. 点击“知识碎片”；
2. 输入一个知识点或问题；
3. 保存 AI 生成的可选结构；
4. 使用主干、分支聚焦、搜索和知识宇宙持续维护。

## 6. GraphRAG 相比普通 RAG 的优势

| 维度 | 普通向量 RAG | MindGrow GraphRAG |
|---|---|---|
| 入口 | 找语义最相似的文本块 | 先找论文名、模型名、实体、指标等高区分度节点 |
| 上下文 | 相似段落的平面列表 | 实体的父子、兄弟、关联和来源文档邻域 |
| 同义/同名问题 | 容易把相似但不同对象混在一起 | 图谱和来源共同约束候选范围 |
| 多跳问题 | 依赖单个文本块碰巧包含完整答案 | 沿两跳关系组合相关证据 |
| 可解释性 | 只看到被召回的段落 | 同时看到入口节点、邻域规模、来源数、证据块和 Citation |
| 知识治理 | 文档越多越容易噪声上升 | 可以发现重复、冲突、孤立节点和跨库主题关系 |

GraphRAG 的关键不是“多画一张图”，而是让图谱真正约束检索：先确定讨论的是哪个实体和哪篇来源，再去做全文/向量召回与重排。这样能够减少“语义相似但事实对象错误”的回答。

## 7. 当前边界

- 跨库关系目前是发现与导航层，不会自动把所有知识库混合回答；
- 中文解析结果已强制输出简体中文，引用原文仍保留原始语言，避免伪造翻译后的“原文”；
- 图片型 PDF 会保留图片页提示，但图表数值仍需要视觉模型复核；
- 知识宇宙为避免浏览器性能下降，每个知识库最多展示 90 个节点，完整数据仍保留在知识库内。
