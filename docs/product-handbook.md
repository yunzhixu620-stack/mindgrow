# MindGrow 产品与技术说明书

## 一句话定位

MindGrow 是面向研究、产品与会议知识的证据型 AI 工作区：低摩擦采集信息，用混合检索与 GraphRAG 定位来源，生成带引用的回答，再沉淀为可编辑、可搜索的知识网络。

## 产品结构

| 板块 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 知识碎片 | 短文本、长文本、公开网页 | 短文本拓展；长文本分层压缩；网页先抓取，失败则拒答 | 渐进展开导图、可检索节点 |
| 文章解析 | 网页、PDF、正文 | 分块、引用校验、实体与关系抽取、GraphRAG | 结构化摘要、问答、知识图谱、Audio Overview |
| 会议助手 | 会议记录或转写文本 | 结论/行动项/负责人/期限/风险抽取 | 会议知识图；确认后进入长期知识库 |

三板块共用统一知识宇宙。文章和碎片可直接形成长期知识；会议内容必须由用户确认后才进入长期库。

## 为什么不是 Notion 或 Obsidian 的替代品

- Notion 的强项是团队文档与数据库；MindGrow 的优势是围绕来源证据做自动抽取、拒答和跨材料检索。
- Obsidian 的强项是本地 Markdown 与手工双链；MindGrow 的优势是自动实体关系、GraphRAG 与三类专用 AI 工作流。
- MindGrow 当前在通用编辑器、插件生态、离线控制和成熟协作上都不如它们，不应宣传为全面替代。

## 技术栈与原因

| 技术 | 选择原因 |
|---|---|
| Next.js 15 + React | 静态公开页可部署到 GitHub Pages并被索引；工作区保持组件化 |
| Supabase Auth + Postgres + RLS | 登录自动续期、结构化数据、租户隔离和可审计迁移 |
| 阿里云函数计算 | 服务端密钥隔离、按量成本、中国网络与冷启动治理 |
| DashScope | 结构化整理、回答和实体抽取；可配合确定性降级 |
| 混合检索 + GraphRAG | 同时利用关键词、语义、实体和路径，减少“语义相近但答案错误” |
| React Flow + PDF.js | 渐进展示大图谱，并支持 PDF 页码与原文定位 |

## 鉴权与普通用户门槛

普通用户只需要邮箱与密码：

1. Supabase 管理登录会话并自动续期；访问令牌不展示给用户。
2. 工作区选择只保存 workspace ID，它不是授权令牌。
3. 每个 API 请求自动携带登录令牌和工作区 ID。
4. 服务端仍验证登录用户是否是该工作区成员；不能只凭 workspace ID 访问数据。
5. 密钥、服务角色和模型凭证不进入前端。
