# MindGrow On-call 与反馈机制

## 1. 服务目标

| 服务 | SLO | 延迟/质量目标 |
|---|---:|---|
| GitHub Pages 前端 | 99.9% | LCP p75 <2.5 秒 |
| 阿里云 API | 99.5% | 非生成接口 p95 <1.5 秒 |
| AI 知识生成 | 99.0% | 完整响应 p95 <12 秒 |
| 知识问答 | 99.0% | 引用覆盖率 ≥95%；越权泄漏 0 |

## 2. 分级

- **SEV0**：密钥/个人数据泄漏、跨租户越权。立即停用相关凭证或入口，15 分钟内响应。
- **SEV1**：核心创建/读取/问答不可用，影响 >10% 用户。30 分钟内响应。
- **SEV2**：部分功能、单一依赖或性能显著退化。4 小时内响应。
- **SEV3**：低影响 UI、文案、单用户问题。下一工作日处理。

## 3. 合成监控

- 每 5 分钟：`GET /health`，非 200 或 `knowledgeStore != ok` 告警。
- 每 15 分钟：列出 maps/categories/default map。
- 每 60 分钟：问候意图，不调用付费生成。
- 每天：一次知识生成检查，验证模型输出结构。
- 每次发布：运行 `npm run test:e2e:local` 与 `npm run test:backend`。

## 4. 当前事故 Runbook：Supabase 不可达

症状：阿里云入口可访问，聊天问候成功，但所有知识 CRUD 返回 5xx；DNS 无法解析 Supabase 项目域名。

处理：

1. 在 Supabase 控制台确认项目是否存在、暂停或已删除。
2. 若原项目无法恢复，创建新项目并运行 `supabase-schema.sql`。
3. 将新 URL 与 server-only service-role/secret key 写入阿里云函数环境变量。
4. 部署最新版 `fc-proxy/index.js`。
5. `/health` 必须返回 200；随后 `npm run test:backend` 应为 13/13。
6. 若恢复失败，前端继续保持本地模式，并在状态页说明云同步不可用。

## 5. 国际用户反馈群

推荐建立三个入口：产品内赞/踩和“报告问题”、英文 Discord 社区、每月一次英语用户圆桌。每条反馈必须带：匿名 query id、语言/地区、场景、知识源类型、预期结果、实际结果、严重级别与是否允许用于评测。

闭环节奏：24 小时内分流 → 每周整理 Top 5 问题 → 建入评测集 → 发布后回访原反馈用户 → 月度公开 changelog。禁止在公开群收集原始企业文档、访问令牌或敏感对话。
